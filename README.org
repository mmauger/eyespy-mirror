Although Emacs has an integrated elisp debugger, sometimes it is
easier to debug what is happening in a function by just displaying
the value of a variable in the midst of running code.  Some of us
are easily distracted (*cough* ADHD *cough*) and we forget what we
were doing between realizing that there is an error, instrumenting
the function for debugging, and then relaunching the failing
function again.  By leaving a breadcrumb in the code itself and in
the `*Messages*' buffer, we are reminded two days later of the
problem we originally encountered before we had embarked on several
unrelated side quests.  To minimize the impact to running code, this function simply just prints the value of an expression in the *Messages* buffer, and avoids pausing execution or significantly interfering with display
processing.  And finally, to simplify identifying debugging code
and messages generated by such code, the macro to invoke the
debugging messaging is a visible Unicode character, and the
messages are preceded by that character as well.

As an example, eyespy messaging can be invoked as follows:

    (defun example-function (alpha beta)
      "This is an example of a function taking ALPHA and BETA parameters."
      (👀 "My system is %s" system-type)
      (👀 alpha beta (+ (if alpha 100 10) beta))
      (if alpha
          (+ beta 100)
        (👀 "Alpha is nil")
        (+ beta 10)))

If the function `example-function' were invoked as follows:

     (example-function "meaningful alpha text" 27)
       ⇒ 127
     (example-function nil 27)
       ⇒ 37

the *Messages* buffer will contain:

     👀 (example-function "meaningful alpha text" 27)  ⟼  My system is gnu/linix
     👀 (example-function "meaningful alpha text" 27)  ⟼  alpha="meaningful alpha text" · beta=27 · (+ (if alpha 100 10) beta)=127

     👀 (example-function nil 27)  ⟼  My system is gnu/linix
     👀 (example-function nil 27)  ⟼  alpha=nil · beta=27 · (+ (if alpha 100 10) beta)=37
     👀 (example-function nil 27)  ⟼  Alpha is nil


The `eyespy-message' function, which the `👀' macro invokes, has
the following behavior:

+ The message line will be prefixed by the macro name.

+ Following the macro name will be the calling function and it's
parameter's values.

+ There will then be an arrow to point out the message being
displayed.

+ If the macro is invoked and the first parameter is a string
literal, then it operates the same way that `message' or `format'
does—the first parameter is a formatting string and the remainder
of the parameters as substituted into the output according to the
formatting rules.

+ If the first parameter to the macro is not a string literal, then
each parameter is formatted with the parameter text followed by
it's evaluated value.  Any nil literal parameters are ignored, so
that the first parameter can be nil to force this second style of
formatting.

+ The evaluated parameters of the macro are returned by the macro.
If there is only one evaluated parameter then it is returned
directly; multiple parameters are returned in a list.  Thus you can
surround expressions with a macro expression and it will appear in
the `*Messages*' buffer and will return its value to the
encompassing expression.  For example, below, the values of `gamma'
and `epsilon' will appear in the `*Messages*' buffer, but their
values will be passed through to the surrounding expression as if
the eyespy messaging wasn't present.

     (let ((gamma 11)
           (epsilon  33))
       (+ (👀 gamma) (👀 epsilon)))
       ⇒ 44

In the `*Messages*' buffer:

     👀 eval  ⟼  gamma=11
     👀 eval  ⟼  epsilon=33

The use of the eyespy icon as the macro for messaging makes
locating these debugging calls in code easy to find with a simple
`grep' command, and also prefixing messages with the icon makes
finding them in the `*Messages*' buffer simple with
\\[isearch-forward] or \\[occur].
